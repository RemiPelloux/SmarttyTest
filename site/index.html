Balanced mode

The default for pull requests and hooks. Every change counts, and a test behind an import SmartTest cannot resolve is selected on its own instead of being ruled out.

Rules can only make the mode stricter. A file marked critical upgrades the whole decision to SAFE.

Safety mode

What happens on a commit

  1. First, the change. SmartTest reads what changed from Git: the staged files in a pre-commit hook, the working tree, a branch against its merge-base, or any commit range. Without Git it compares local snapshots of the project.

    ◇ git · HEAD…index (staged) · 1 changed file(s) · mode balanced
    modified src/modules/auth/TokenManager.ts implementation

  2. Then, the declarations. Each changed line is mapped to the method, function or class around it and classified as comment, formatting, implementation, signature or exported API. An edit inside verify is a change to TokenManager.verify, not to every user of the file.

    changed unit src/modules/auth/TokenManager.ts#TokenManager.verify
    not changed TokenManager.issue · the class shell · the file's module code

  3. Then, the graph. From the changed method SmartTest walks backwards to every test that can reach it, through imports, re-exports, barrels, inheritance, CommonJS, path aliases and workspace packages. Environment keys, Prisma models, translation keys and files read with fs are nodes too, so a change to one key reaches only the code that reads it.

    TokenManager.verify → AuthService.validateToken → authenticate → protectedRoute → test/routes/ProtectedRoutes.test.ts
    i18n:greeting → src/greet.ts#greet → tests/greet.test.ts

  4. Then, what it cannot see. An import it cannot resolve is never treated as unrelated: the tests behind it run. When smarttest trace has recorded which functions each test ran, a test that can reach the change on paper but never ran the changed code is skipped, with the date of the trace as its reason.

    SKIPPED (not run) tests/price.test.ts
    • Reachable statically, but its trace (2026-10-29) never ran the changed code

  5. Last, your runner. The selected tests run through the project's own Jest, Vitest or node --test configuration. The report lists every skipped test as not run, never as passed.

Try it on your repository

SmartTest is not on npm yet. These commands build it from the repository, install it in your project and preview the setup. Nothing is written until you run init --yes.

Set up SmartTest

Node.js 22.12 or newer · Jest, Vitest or node --test

git clone https://github.com/RemiPelloux/SmarttyTest ~/SmarttyTest
cd ~/SmarttyTest && corepack enable && pnpm install && pnpm release:pack
cd ~/code/my-app
npm install -D ~/SmarttyTest/packages/cli/.publish/smarttest-{{VERSION}}.tgz
npx smarttest init --dry-run

SmartTest runs only the tests a change reaches, and says why for every test it skips.
