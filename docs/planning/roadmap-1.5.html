Version 1.2.0

Roadmap to 1.6.0

1.0.0 froze SmartTest's contracts. The 1.x line keeps them: every version from 1.1.0 to 1.6.0 is additive (new flags, new config keys with defaults, new adapters), so a config, a script or a --json consumer written for 1.0.0 keeps working. Anything that would break a frozen contract waits for 2.0.0 (contracts).

The first real rollout after 1.0.0 set the order. On 1 November 2026 SmartTest went into four of OpenPro's repositories (front, admin, desktop monitor, MCP service): 0 missed failures and 42–96% less test time, but each repository needed hand work that init should have done, and a bug hid one test file. 1.1.0 adds Angular, proves selection is reliable with checks that inject real faults, brings Python forward as a preview, and makes that hand work unnecessary. OpenPro's backend needs PHP next, so 1.2.0 brings a PHP preview forward, with what the 1.1 rollout left open and the first precision stories. Then the rest of precision (1.3.0), the browser (1.4.0), the ecosystem (1.5.0) and the backend frameworks (1.6.0).

Planning is in story points; one sprint is about 40 points. A version ships when its gate is met, not on a date. Sprints continue from S27 (1.0.0).

S28: Angular (40 pts) #

Angular is the main TypeScript framework SmartTest does not understand. Most of an Angular app is ordinary TypeScript and is already analysed, but three things are missing. First, components load their template and styles by path (templateUrl, styleUrl), not by import. Today a change to foo.component.html selects no test at all, not even foo.component.spec.ts; that is a missed test, not only a missing feature. Second, tests run through ng test, not through a runner config. Third, angular.json holds what other projects keep in tsconfig and runner configs.

StoryPts
Component resources are edges. templateUrl, styleUrl and styleUrls in @Component link the component to its template and styles, and Sass/Less @use/@import link a stylesheet to its partials. A template or style change selects the tests of that component and of its importers. A path that cannot be resolved is uncertainty. New edge type: a fixture where a template change selects only its component's specs.5
Angular workspaces detected. angular.json (and Nx project.json) read for each project: root, sourceRoot, the tsConfig of its build and test targets, fileReplacements (a change to environment.prod.ts selects the tests of environment.ts's importers) and global styles/scripts. detect and doctor report Angular and its version; init proposes the matching runner and scope.5
ng test as a runner. An adapter for the Angular CLI's test builders: @angular/build:unit-test (Vitest, the default since Angular 21) and the Karma builders. It reads include, exclude, setupFiles, providersFile, polyfills and tsConfig (all of them runner inputs, so a change selects that project's tests), and runs a selection with ng test --include per project. Karma reports per file only; the adapter declares it and does not emulate per-test results (ADR-0005). A run where ng test fails before reporting is a failure, never a pass.13
Jest and Vitest community setups. jest-preset-angular (setup-jest.ts, zone setup), @angular-builders/jest (Jest config inside angular.json) and @analogjs/vitest-angular discovered and run through the existing Jest and Vitest adapters.5
Angular code edges. Lazy routes (loadComponent, loadChildren with import()) link the route file to the loaded code; the legacy string form ('./x.module#XModule') is resolved, or treated as uncertainty when it cannot be. inject(X), constructor injection and providers need nothing new, since they import their tokens; a fixture proves it.5
Fixtures and a real-world check. Three fixtures: a standalone Angular 21 app on the unit-test builder, an NgModule app on Karma, and an Nx workspace on Jest. An open-source Angular application replayed with benchmark and added to the published benchmarks. The trace and resolution oracles from the 1.0.2 audit are run on it, with a trace that also records the non-code files a spec reads (templates, styles, JSON), which the 1.0.2 trace could not see.5
Angular guide. documentation/guides/angular.md: what is understood, what is uncertainty, the supported builders, and how to read explain on a template change.2

S28 gate: on the three fixtures, a template, style, component, service or angular.json change selects the affected specs and no others. The full suite through SmartTest reports the same tests and failures as ng test. benchmark on the open-source application shows 0 missed failures, and the trace oracle finds no file a spec loads that selection cannot reach.

S29: Reliability (40 pts) #

The 1.0.2 audit found about 30 ways a change could skip a test it affects. It was run by hand, once. This sprint makes those checks part of SmartTest and of every release, adds the one check that measures misses directly (inject a fault, see which tests fail), and closes the two correctness items the OpenPro rollout found.

StoryPts
Fault injection. smarttest audit --mutate changes one function at a time in a real way (makes it throw, or return a wrong value), runs the full suite, and reports every test that failed without being selected. That is a missed test by definition, with no guessing from the graph. It samples functions across the repository within a time budget and never leaves a change behind (it works on a copy).8
Reachability audit as a command. The trace oracle from the 1.0.2 audit becomes smarttest audit --traces: every file a test loaded or read at run time (code and non-code: templates, styles, JSON, fixtures) must be reachable from that test in the graph, or reached by a runner input or uncertainty. The resolution oracle (each import resolved as the TypeScript compiler resolves it) becomes smarttest audit --resolution.8
Audits in CI. A nightly job runs the three audits on every fixture and on the benchmark repositories; any missed test or unreachable file fails it. Each release runs them on the adopting projects and records the result in the delivery log.5
Fail-safe under faults. Every internal error, timeout, corrupt or half-written state file, missing Git, killed runner and lost lock ends in a full run with a warning, never in a smaller selection or a pass. A fault-injection test suite proves each case.5
Flaky failures told apart. When benchmark or audit sees a failure, it reruns that test alone on the parent commit and on the change. A test that fails only under load is reported as load-flaky, separately, and never counted as a miss or as a pass. (1.0.2: MiaDock.test.tsx, tournament-pool.test.ts.)3
No test file is ever invisible. The built-in ignored directories (build, out, dist…) are skipped as build output, but a file the runner itself collects is always analysed: discovery's list wins over the walker's ignores. doctor and scan report any file a runner collects that the graph lacks. (OpenPro: src/tests/build/…test.ts was never selected.)5
it.each rows keep their own identity. A test id holds the row's formatted title, or its index when titles repeat, so reports, the result cache and flaky history count every row. (OpenPro: 8 passing rows counted as fewer.)3
Reliability report. audit writes one report: missed tests, unreachable files, flaky tests, fail-safe triggers, and the share of functions checked by fault injection. Published with the benchmarks.3

S29 gate: on the fixtures and the benchmark repositories (the five adopting projects and the Angular application), fault injection finds 0 missed tests, the reachability audit finds 0 unreachable files, and every fail-safe case ends in a full run.

S31: Rollout without hand work (32 pts) #

Every item comes from a problem met on OpenPro. Each was fixed by hand there; here it becomes the default. The two correctness items found there moved to S29.

StoryPts
Pre-push reads Git's refs wherever the step runs. When the refs are missing, run --push falls back to the upstream merge-base with a warning instead of ST_HOOK_PUSH_REFS_MISSING; hook install rewrites a backgrounded test step (… &) to receive the refs it saved.5
init respects the hook a repository already has. It detects hook installers that copy scripts (cp scripts/pre-commit $(git rev-parse --git-path hooks)) and edits the source script, not the copy in .git; when an existing hook already runs related tests (vitest related, jest --findRelatedTests), it replaces that step in place, in the same hook, instead of adding a second one elsewhere.8
--runner <name> on run, impact, benchmark and validate-selection. Today keeping Playwright out of a parity check or a benchmark needs a copied config. benchmark follows hook.runners unless told otherwise.3
Lockfile changes select by package. A package-lock.json, pnpm-lock.yaml or yarn.lock change is diffed: only the packages whose resolved version changed select the code that imports them (and their tests). Today any lockfile change selects every test, which put a 4-minute estimate on a one-line push. A lockfile that cannot be parsed still selects everything.8
The hook budget explains itself. When an estimate passes hook.budgetMs, the warning names the trigger that widened the selection (a lockfile, a config file) and the files with no recorded duration.3
Rollout guide and case study. documentation/guides/rollout.md from the OpenPro migration: parity check, benchmark, hooks per repository, what to leave to CI; the four repositories added to the published benchmarks.5

S31 gate: on a fresh clone of each of OpenPro's four JavaScript repositories, smarttest init --yes alone produces a setup equivalent to the hand-tuned one (hook, scope, script placement), the full suite through SmartTest reports the same tests and failures as the runner, and benchmark shows 0 missed failures. No test file a runner collects is missing from the graph in any benchmark repository.

S31 status (3 November 2026): delivered; gate met for the setup, the published benchmarks not updated.

  • Delivered: pre-push without Git's refs on stdin compares with the upstream merge-base, and hook install gives the refs to a backgrounded test step; hooks copied into .git/hooks by a script are edited at their source, and init replaces a test step in place; --runner on run, impact, validate-selection and benchmark; lockfile and package.json changes select by package; the hook budget warning names what widened the selection; the rollout guide.
  • Lockfiles on opal-frontend's 12 dependency updates: a @types/lodash bump selected 0 of 351 specs instead of all; the other 11 still run everything, each for a stated reason (the Angular builder and the test runner, packages a setup file or a script loads).

S32: PHP preview (40 pts) #

SmartTest stays an npm package. It reads PHP source in TypeScript, without running PHP, and runs the project's own vendor/bin/phpunit (or php artisan test, or Pest) as a subprocess, as the Python adapter runs pytest. A PHP repository needs Node on the machine, not a package.json.

StoryPts
PHP analysis. Namespaces; use statements (grouped, aliased, use function, use const); classes, interfaces, traits and enums with their methods, constants and properties; extends, implements and trait use as edges; names in the same namespace used without use. Files found through composer.json (autoload and autoload-dev: PSR-4, PSR-0, classmap, files) and require/include of literal paths. A method used through $this->, self::, static:: or a typed parameter links to that method; any other use links to the whole class.13
Laravel container edges. Facades link to the class behind them (getFacadeAccessor, the aliases in config/app.php); bind, singleton and scoped in service providers link an interface to its implementation; app(X::class), resolve() and make() link to X; the providers in bootstrap/providers.php are loaded by every test that boots the application.5
Unresolvable means selected. Dynamic names (new $class, $class::$method(), app($name), call_user_func with a variable, string class names built at run time) are uncertainty and select the tests that reach them, as in TypeScript and Python.3
PHPUnit and Pest runners. Tests discovered from phpunit.xml (testsuites, directory, suffix, exclude) and listed with --list-tests-xml; a selection run by file with results read from --log-junit; php artisan test and Pest detected and used when the project uses them. phpunit.xml, its bootstrap, tests/TestCase.php, .env.testing and database/migrations are runner inputs: a change to them selects every test that boots the application. A fatal error, a test file PHPUnit collects nothing from, or "No tests executed" is a failure, never a pass.8
Hooks in a PHP repository. init on a repository with composer.json and no package.json: SmartTest runs through npx, php.enabled and php.binary in the config, and a CaptainHook action that already runs changed tests (scripts/test-changed.sh) is replaced in place, as S31 does for Husky.3
Fixtures and OpenPro's backend. A plain PHPUnit fixture and a Laravel fixture (facade, container binding, feature test with RefreshDatabase); openpro-backend checked for parity, replayed with benchmark and audited with audit --resolution --mutate.5
PHP guide. documentation/guides/php.md: installing with Node beside PHP, what is understood, what is uncertainty, how to turn the preview off.3

S32 gate: on openpro-backend, the full suite through SmartTest gives the same results as php artisan test; benchmark shows 0 missed failures with less test time than the full suite; fault injection finds 0 missed tests; init --yes replaces test-changed.sh in its CaptainHook hooks. The preview can be turned off per project.

On openpro-front that meant 14,377 changed files and a 27-minute hook. Selection precision report. benchmark adds the share of selected files that actually ran the changed code (from traces), so precision is measured, not only safety.8

S34: Hooks and CI (27 pts) #

StoryPts
Commit trailer. A commit hook can add a trailer to the commit message with what the pre-commit run did (Tests: 12 run, 2,340 not run · 4 min saved), opt-in with hook.trailer; hook install adds the commit-msg step for Husky, lefthook, simple-git-hooks, CaptainHook and plain hooks. Replaces openpro-backend's scripts/test-trailer.sh. A commit whose tests were not run (bypassed, no record for the staged tree) gets no trailer, never a false one.5
Playwright projects understood; live specs. Moved from 1.4.0. Each project's baseURL, dependencies (setup projects) and testMatch read from the config; a spec that only targets a remote baseURL (https://…, not localhost) is marked live and never run by run, benchmark or a hook unless asked (--live).8
CI annotations. Moved from 1.5.0. GitHub Actions, GitLab CI and Bitbucket: selected and skipped tests as annotations on the pull request, with the explain reason; a step summary with time saved.8
Upgrade assistant. Moved from 1.5.0. smarttest sync proposes config changes for new 1.x features (lockfile selection, live specs, type-checker), shown as a diff, never applied silently.6

S35: Laravel routes (15 pts) #

S32 made PHP selection correct on openpro-backend but not faster: every feature test boots the application, the application loads every route, and every route reaches its controller, so any change under app/ selects all 1,998 test files.

StoryPts
Routes as edges. routes/*.php read statically (verbs, resource/apiResource, groups with prefix, middleware and controller, names, model binding): each route links to its controller action and the middleware, form requests and policies it names. A change to a route file, global middleware, a provider or the configuration still selects every booting test.5
Requests as edges. The URLs and route names a feature test requests (get, postJson, route('name'), action([…])) link the test to the matching routes, not to every route. A request whose URL cannot be read statically is uncertainty for that test only.5
Run-time class choices. $class::…, new $class and app($class) where $class comes from a literal map, match or config array of X::class values link to those classes; the rest keeps // smarttest-loads:.3
Fixture and openpro-backend. A routes fixture where a controller change selects only its route's tests; openpro-backend replayed with benchmark and audited.2

S35 gate: on openpro-backend, benchmark shows 0 missed failures and less test time than the full suite, with a controller change selecting only the feature tests that request its routes; fault injection on the PHP fixtures finds 0 missed tests.

S35 status (6 November 2026): delivered; gate met (openpro-backend measured on a clone with three smarttest-loads comments added).

  • Delivered: route files read statically (verbs, match, resource/apiResource with only/except, groups with prefix, name, middleware and controller, fluent or array attributes, included route files, invokable, string and closure actions); each route is a symbol linked to its action, its controller's constructor and its middleware. Tests' requests (get/postJson/…, json/call, concatenated, interpolated, sprintf, constant, url() and route('name') urls) link the test to the routes that serve them; request helpers (authenticatedRequest($method, $uri)) take their callers' urls; $this->artisan('x:y') links to the command whose $signature names it. The boot loads route files, migrations, translations, views, commands and the providers list without using what they name. Class values read from match arms, config lists (config('prospection.connectors')) and private methods' literal callers. Found on the way: parent::setUp() made a change to one test's setUp reach every test (fixed for every language), and under php artisan test the boot is now reached through the graph instead of its import closure.
  • openpro-backend: the remaining uncertainty after the generic readings is three lines, which the maintainers would annotate (added on the clone only, applied under each replayed commit): app/Services/Advertising/AdOwnership.php before $class::query() — // smarttest-loads: app/Models/**/*.php; app/Support/AI/Live/Admin/Catalogue/AdminEndpointRules.php before new $form — // smarttest-loads: app/Http/Requests/**/*.php; tests/Support/TestBootCache.php before require $bootstrapFile — // smarttest-loads: bootstrap/app.php. Without them every test that boots the application stays uncertain.
  • benchmark on the last 10 commits: 0 missed failures, 47% less test time (1,670.5 s against 3,146.1 s for the full runs; the full runs were slowed by load on two commits, 562 s and 346 s against about 265 s). Four commits select every test, each for a reason that holds: rate limiters registered by AppServiceProvider::boot, an edit of routes/web.php, config/crm.php and config/prospection.php. The others select 182–537 of 1,998 files; 182 tests stay selected on any change (requests built at run time, routes registered inside tests, helpers called with a computed url).
  • Fault injection: the PHP fixtures, 0 missed (31 functions). openpro-backend (audit --resolution --mutate --mutants 5, 27 minutes): 5 faults, 3 caught, 2 survived (both in vendored JavaScript under public/ that no test runs), 0 missed; resolution 116 of 116 JavaScript imports agree.

1.3.0: Precision (52 pts) #

Run fewer tests for the same safety. Two items have been carried since 0.3.0 and 0.8.0. Barrel pruning, the lazy index and the precision report moved to S33.

StoryPts
Type-checker resolution for calls local inference cannot type (values from factories, generics, injected dependencies). A call resolved by the checker selects the callers of that method instead of the whole class. Opt-in per project at first (analysis.typeChecker), with a time budget; on budget overrun it falls back to today's class-level selection, which is safe.21
Observed execution, second pass. Traces recorded per test file narrow a static selection only where both agree; trace --stale refreshes the traces a change invalidated. Target carried from 0.5.0: 20% fewer test files than static selection, at 0 misses.13
Speed target carried from 0.8.0. 30% less wall-clock time than 1.0.0 on the published benchmarks, from the lazy index, earlier fail-fast ordering and runner warm-up reuse.13
TypeScript 7 parser. Adopted when its parser API leaves unstable/*; until then a watch item with a compatibility test against each 7.x release.5

Gate: type-checker resolution on at least two benchmark repositories with 0 misses; the 20% observed-execution reduction met on at least two of them.

1.4.0: Browser and end-to-end (64 pts) #

End-to-end specs are where test time goes, and where running the wrong one is costly: on OpenPro, the Playwright suite targets a live environment.

StoryPts
Browser coverage through source maps. Bundled and transpiled scripts mapped back to their sources, so a spec is linked to the components it actually rendered; Chromium first, then Firefox and WebKit where Playwright exposes coverage.13
Pages beyond the page fixture. New pages, popups and context.newPage() traced and mapped to their routes.5
Route-level selection for single-page apps. React Router, TanStack Router and Vue Router routes mapped to the specs that visit them, as Next.js routes are today.13
Cypress component tests selected like unit tests, with coverage.8
End-to-end sharding by recorded duration across CI machines, with setup projects run once per shard.8
Studio sign-off carried from 0.9.0. Full-screen design review in both themes, forced colours, text spacing, VoiceOver live regions.8
Visual and snapshot specs. Screenshot baselines (toHaveScreenshot) linked to the components and styles they cover; a style change selects them.9

Gate: on OpenPro's front, a component change selects the Playwright specs that render it, from source-mapped coverage; 0 missed failures across the end-to-end benchmarks.
