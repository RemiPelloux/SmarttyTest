Version 0.9.0

Roadmap to 1.0.0

1.0.0 is the version we can recommend for any TypeScript/JavaScript repository: selection precise enough to matter on large codebases, never wrong in a way that hides a failure, fast enough to sit in a pre-commit hook, and installable from npm.

The dependency graph is the product. Most of this roadmap makes it more precise (fewer tests run for the same safety) and more complete (fewer relationships SmartTest cannot see).

Planning is in story points. One sprint is about 40 points. Each version has an exit gate; a version ships when the gate is met, not on a date.

Where 0.9.0 stands #

  • Released: 0.3.0 to 0.9.0 on top of the foundation backlog. Sprint-by-sprint results, partial items and what moved: delivery log.
  • Graph today: files, top-level symbols and class members; imports, re-exports, barrels, workspace packages, CommonJS, inheritance; environment keys, Prisma models, translation keys, assets, snapshots, manual mocks, Wasp operations, Next.js routes and the URLs end-to-end specs visit; runtime traces as observed evidence. Unresolved relationships are uncertainty and select the test.
  • Runners: Jest, Vitest, node --test, Playwright, Cypress. Version control: Git, Subversion, Mercurial, native snapshots.
  • Real-world checks: LeadsIt (706 tests) and four public repositories set up with init --yes, 0 missed failures in every replay.
  • Still open before 1.0.0: npm publication (name decision), macOS and Windows validation, cold start and warm analysis at 2,000+ modules, and the 0.5.0/0.8.0 performance targets, which were not reached on LeadsIt.

Every new edge type follows the same rules as today: if SmartTest cannot evaluate a relationship, it records uncertainty and selects the test instead of guessing.

0.3.0: Precise graph (96 pts planned, 83 delivered), released #

Selection moves from "the class changed" to "this method changed, these callers use it".

StoryPtsStatus
Member-level resolution: obj.method(), property access and construction resolved to the declaring member through local inference (new X(), x: X, constructor parameter properties, this.p); values that escape or whose class is unknown stay class-level21done
Method-level propagation: methods and accessors are units of their own; constructor, field and heritage changes stay class-level13done
Inheritance and overrides: inherited members resolve to the base class, overrides only to the subclass, super.m() to the base member8done
CommonJS at symbol level: module.exports = { a, b }, exports.a =, destructured and namespace require13done
Re-export hardening: export * as ns, default re-exports, export =, circular barrels8done
Persistent graph with incremental patches13moved to 0.8.0: rebuilding from cached analyses stays under 200 ms at 2,000 modules
Graph diff between revisions: dependencies added or removed by the change, shown in impact and the decision8done
Queries: graph why <a> <b>, graph cycles, graph orphans8done
Decision confidence: lowest edge confidence along the path, shown in reasons and explain4done

Type-checker resolution for values local inference cannot type (return values of functions, generics) is moved to 0.8.0; until then those calls are class-level, which is safe.

Gate: method-level fixture passes (a change to TokenManager.verify no longer selects AuthController, which only reaches issue); regression harness at 0 missed failures. LeadsIt measurement after 0.5.0.

0.4.0: Complete graph (92 pts planned, 84 delivered), released #

Changes that are not TypeScript code used to fall back to whole files, whole projects or "not analysed". Each of these now has real edges.

StoryPtsStatus
Environment edges: process.env.X, process.env["X"], destructuring and import.meta.env.X create edges per key; editing one key in .env* selects only its readers. A key no code reads keeps the mandatory trigger13done
Asset edges: JSON, YAML, CSS, SQL and text imports (already tracked as files); readFile / readFileSync / createReadStream with paths built from __dirname or import.meta8done
Framework conventions: Wasp operations imported from wasp/client/operations and wasp/server/operations resolve to the implementation declared in main.wasp.ts. NestJS constructor injection is covered by parameter-property inference (0.3.0) and Express routers are plain imports13done
Next.js app/ and pages/ route conventions and middleware8moved to 0.7.0, with E2E route mapping
Database schema: Prisma models and enums linked to prisma.<model>, db.<model>, Wasp context.entities.<Model> and type imports from @prisma/client / wasp/entities; datasource and generator changes widen to the schema's directory13done
Translations: t("key"), t(\prefix.${x}\), i18nKeylinked to catalog keys (TypeScript or JSON catalogs underlocales/, i18n/, lang/, translations/, messages/); t(variable) reads any key8done
Test infrastructure: snapshot files select their test, __mocks__/x selects the users of x, fixtures read through fs are asset edges, import.meta.glob is an import. Setup files stay mandatory triggers8done
Mock awareness: a test that replaces module M with a factory (vi.mock / jest.mock with a factory that does not load the original) does not run M; implementation changes in M, or in modules only reached through M, skip it. Signature changes still select it13done
Generated code: generated[].from lists generator inputs; with rebuild-required, an input change stands for a change to the outputs and warns to regenerate8done

Gate: met. The edges-vitest fixture has one targeted change per edge type that selects only the affected tests (integration-tests/edges.test.ts), and its seven seeded mutations are in the regression harness with 0 missed failures in BALANCED and SAFE.

0.5.0: Runtime evidence (71 pts), released #

Static analysis says what can be reached; runtime traces say what is actually executed.

StoryPtsStatus
Per-test-file V8 coverage for Vitest, Jest and node:test (smarttest trace), stored as observed execution with file hashes and a runtime/lockfile fingerprint21done
Trace invalidation: a trace is used only while every file it loaded is unchanged at the base of the change; stale traces are ignored; trace --stale refreshes them8done
Hybrid selection: traces rule out static-only and uncertainty selections in FAST/BALANCED and add tests static analysis missed; SAFE only adds; explain shows the trace8done
Unprotected changes: changed units no test reaches statically or in a fresh trace, listed by impact13done (unit level; line-level coverage is not reported)
Shadow Mode: smarttest shadow and shadow --report13done
benchmark --since <ref> with --sample, --resume and --traces8done

Gate: partly met. 0 missed failures on the fixtures, on 12 replayed LeadsIt commits with traces, and on 40 commits sampled from the last 200. Observed execution reduced the LeadsIt selection by one test file (11 → 10 on the commits without lockfile changes), short of the 20% target: static selection there is already narrow. The 200-commit Shadow Mode run is not done; it needs a repository with a longer-running suite to be meaningful, which is part of the 0.6.0 external-repository work.

0.8.0: Speed (105 pts), released #

Run less (graph), then run what remains faster.

StoryPtsStatus
Validated result cache, content-addressed on the test, its closure and traced files, runner config, manifests, lockfiles, env and setup files, runtime and runner version; cached results always reported as cached21done; benchmark checks every cached pass against the full run
Fail-fast ordering: recent failures first, then the tests closest to the change; --bail8done
Duration-aware scheduling: independent runner groups in parallel within a CPU budget13done (parallelGroups, end-to-end groups alone); memory is not budgeted separately
Sharding: smarttest shard --total n --index i and run --shard i/n, balanced by recorded durations8done
Flaky analytics: failure history, rate, retry-rule suggestions (never silent skips)13done
SVN and Mercurial adapters behind the existing VCS contract16done
Persistent graph with incremental patches (from 0.3.0)13partial: in-memory patches in watch (under 1 ms at 2,000 modules); the graph is not persisted to disk, a rebuild from the cached index takes about 60 ms
Type-checker resolution for values local inference cannot type (from 0.3.0)13not done; moved after 1.0.0

Gate: not met. On LeadsIt's last 12 commits, SmartTest's time went from 47.2 s (groups one after another, no cache) to 43.4 s (8% less), with 0 cache-integrity violations and 0 missed failures. Parallel groups help on the commits that run several projects; on single-project commits nothing changes. The result cache never hits when replaying history, because every commit changes the inputs of the tests it selects; it pays off on repeated runs of the same state (re-running after a fix elsewhere, CI retries, switching back to a branch), where a second run of an unchanged selection takes milliseconds.

0.9.0: Commit hooks and interfaces (116 pts), shipped with partial gates #

Three sprints: S24 makes the commit hooks a first-class SmartTest experience; S25 and S26 build SmartTest Studio and the VS Code extension.

S24: Commit hooks (40 pts), implemented #

Pre-commit and pre-push hooks run the hook profile. Staged-content isolation, affected-project checks, duration estimates and history are implemented. Real Git hook fixtures cover partially staged content, alternate indexes, rejected pushes and new remote destinations. Measurements and remaining validation are recorded in the delivery log.

StoryPts
Staged-content runs: run --staged tests exactly what will be committed. Partially staged files and unstaged edits are set aside (a temporary checkout of the index, never a stash that can lose work) and the result says so8
smarttest hook install --pre-push: compares with the actual pushed destination; manual --push uses the upstream or origin, and unknown destinations use the empty tree, replaces vitest related / full-suite steps the same way --replace does for pre-commit5
Hook profile: hooks run with fail-fast order, --bail, the result cache and parallel runner groups by default; output fits one screen (changed files, selected count, failures with their first error lines, total time, "why" command)5
Project checks for affected projects: a hook.checks list (lint, type-check, build…) run only for the sub-projects the change touches, in parallel with the tests, with staged-file arguments where the tool accepts them (ESLint, Prettier)8
Time budget and honesty: hook.budgetMs; when the estimate (recorded durations) exceeds it, the hook says which tests make it slow and offers --shard-free options (run in pre-push instead, trace to narrow); it never skips silently. SMARTTEST_SKIP=1 is recorded; commits without a successful tree record are reported as unchecked, not proven --no-verify bypasses5
smarttest hook status and doctor: hook duration over the last runs (median, slowest), steps that still run whole suites, steps that duplicate SmartTest, missing installs on teammates' machines (hook present, node_modules/.bin/smarttest missing)5
Validation: LeadsIt's husky hook and a pre-push setup like OpenPro's (vitest related + type-check + build) migrated with hook install --replace and measured with benchmark: hook time before and after, 0 missed failures4

Gate: a commit with partially staged files is tested on its staged content; hook time on LeadsIt and on a pre-push setup like OpenPro's is measured before and after with 0 missed failures; no step is skipped without being reported.

S25–S26: SmartTest Studio and the VS Code extension (76 pts), implemented with validation limits #

SmartTest Studio and the VS Code extension: everything the CLI shows, without the CLI. Studio runs locally (smarttest studio), uses the same engine as the CLI through @smarttest/core, and follows the design system of the HTML report and the documentation site. Nothing leaves the machine.

StoryPts
smarttest studio: local web app bound to loopback with a session token and origin checks; project overview (runners, last run, cache, traces, flaky tests) and test explorer21
Impact map: the dependency graph of the current change, path highlighting from a changed method to each selected test, reasons and confidence, filters, export13
Live runner and coverage viewer: run affected, all or one test file; results stream in, cached results marked; source annotated with changed lines, observed execution and unprotected changes21
VS Code extension: "protected by N tests" above each function and method, run the affected tests of the current file, explanations on hover, uses the local smarttest21

Built on what exists: --json outputs (impact, explain, run), the HTML report, watch (in-memory graph patches) and traces.

Studio must be a well-designed product, not a dashboard template. It is built with the frontend design skill's app-screen run, from the Studio design brief: one question per screen, real data from the CLI, the dealt style (data-terminal, on the SmartTest palette) and its signature element, the impact strip.

Gate: run, explain, inspect impact and read coverage without the CLI; the design skill's linter and inspector pass with 0 failures at 1440, 768 and 390 pixels, and the screenshot critique is recorded; WCAG 2.2 AA in both themes and full keyboard use; local security review of Studio passed.

1.0.0: Stable (52 pts, plus items carried from 0.6.0 to 0.9.0) #

StoryPts
Plugin SDK 1.0: frozen adapter contracts (language, runner, VCS, edge providers), conformance kit, documentation13
Freeze public contracts: config schema, exit codes, --json schemas; semver policy and migration notes5
Published benchmarks on at least five real repositories, LeadsIt included, with 0 missed failures; the 0.5.0 (observed execution) and 0.8.0 (speed) targets re-measured there13
Performance: warm analysis under one second at 10,000 modules, cold start under one second at 2,000; the graph persisted between runs8
Security review: file writes, process execution, Studio8
Documentation complete5
Carried: publish on npm (needs ADR-0007), pnpm verify on macOS and Windows, Cypress adapter checked against a real install—

Carried from 0.9.0: a Studio pass with a real screen reader (NVDA, VoiceOver) and real Safari, full-screen design signoff in both themes, and a hook-only runner scope so browser specs can stay in CI. Done in the 0.9.0 validation round: the extension in a real VS Code host (also in CI on Linux, Windows and macOS), an automated WCAG 2.2 AA and keyboard audit in three browser engines, and before/after hook measurements on OpenPro's front end. Studio has path-based impact inspection and unit trace annotations; graph filtering/export, line/branch coverage and browser coverage collection remain open. The extension's file command currently runs the whole affected change set and identifies the file's intersection; true file-scoped selection remains open.

TypeScript 7 stays a watch item: the analyzer moves when TypeScript 7 offers a parser API usable from Node.

Gate: all of the above, and no open defect that can make a failing test be skipped.

Not before 1.0.0 #

  • Type-checker resolution for values local inference cannot type (moved from 0.3.0 and 0.8.0); until then such calls are class-level, which is safe.
  • AI test generation and audit (PRD Release 3): 2.0.0, built on the generator's it.todo scaffolds. The deterministic core never depends on it (ADR-0004).
  • Cloud and team analytics (PRD Release 5).
  • Other languages (PRD Release 6). The edge-provider SDK in 1.0.0 is designed for them.
